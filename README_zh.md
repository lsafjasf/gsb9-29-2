# 协程调度器饥饿修复（Python 3 标准库）

## 1. 问题与根因

`naive.py` 是一个**严格优先级、运行到阻塞/让出才切换**的调度器：

1. 总是选择静态优先级最高的就绪协程；
2. 一旦选中，就把它 `yield Work(B)` 的整段 CPU 突发**不抢占地**跑完；
3. 锁是普通互斥锁，没有优先级继承。

由此产生两个病理学现象：

- **饥饿**：一个高优先级长任务 `Work(B)` 一旦开始，所有低优先级协程在
  整整 `B` tick 内一个 tick 都拿不到——即“只有负载降下来才跑”。
  根因是“优先级高 ⇒ 单轮执行量无上限”。
- **优先级反转**：低优先级持锁者主动让出后，被中优先级 CPU 密集任务插队，
  阻塞在锁上的高优先级任务要等全部中等负载跑完，延迟随中等负载无界增长。

## 2. 修复方案（`scheduler.py`）

把“运行到阻塞”改成**按轮（round）的优先级轮转（priority round-robin）**：

1. 每轮开始对就绪队列做**快照**，按
   `(有效优先级, 全局入队序号)` 排序；
2. 快照中的每个任务本轮**恰好被派发一次**，获得相同的固定预算
   `q = quantum`（模拟 tick）；
3. 超过预算的 `Work` 突发在预算边界被**抢占**，剩余量（`pending_work`）
   下一轮继续；不让步的长任务也不可能连续占用超过 `q`；
4. 同优先级严格 FIFO（序号唯一），优先级只决定轮内位置——因此给定
   **就绪顺序 + 静态优先级，执行序列是唯一确定函数**；
5. 锁实现 **FIFO 唤醒** 与**传递式优先级继承**：持锁者的有效优先级
   提升为所有（传递地）等待其锁的任务中最高者；环（死锁）由访问栈保护。
   唤醒任务统一进入**下一轮**，避免轮内递归交接，使界可以精确陈述。

确定性来源：纯整数模拟时钟、全序排序键、锁队列 FIFO、无 wall-clock/随机输入。

## 3. 等待时长上界推导

记号：轮 `r` 开始时就绪快照大小为 `n_r`，单轮执行量（时间片）为 `q`。

**定理 1（轮内界，紧界）**：对任一轮 `r` 中第 `k` 个被派发的快照任务，
从该轮开始到它拿到 CPU 为止，其前面的任务最多各执行 `q`：

```
W_r(k) ≤ (k − 1)·q ≤ (n_r − 1)·q .
```

- 每任务本轮至多 `q`（超出即被抢占）；
- 每个快照任务本轮恰好派发一次，无新增任务插队（轮中就绪者进下一轮）；
- 因而第 `k` 个任务前面恰有 `k−1` 个任务，服务量之和 ≤ `(k−1)q`。

令 `n_max = max_r n_r`，则**任意轮内等待**

```
W ≤ (n_max − 1)·q .
```

这是**与任何单个任务的突发长度无关**的界：长任务只增加“需要多少轮”，
不增加“低优先级任务在某一轮内被服务到”的时间。饥饿负载中该界取等
（见仿真 `svcWaitMax == (n−1)q`），故为紧界。

**定理 2（跨轮到达的统一界）**：若任务在轮 `r` 进行中变为就绪
（被锁唤醒），它在轮 `r+1` 才被派发：先等完到达轮剩余部分
（≤ `n_r·q`），再在派发轮内排队（≤ `(n_{r+1}−1)·q`）：

```
W ≤ n_r·q + (n_{r+1}−1)·q ≤ (2·n_max − 1)·q .
```

**优先级反转界**：持锁者被继承到高优先级后，在每个轮快照中都排在中优先级
任务之前，因此高优先级等待者的阻塞时间只取决于“低优先级者跑完临界区需要
多少个时间片”，与中优先级任务的总 CPU 量无关：

```
阻塞时间 ≤ ⌈L_cs / q⌉·q + (n − 1)·q  （n 为同时就绪的任务数）。
```

> 测量口径：`svcWait` 是“本轮更早任务实际交付的 CPU tick 数”（即定理中
> 的服务量单位）；`wallMax` 是“就绪→派发”的墙上延迟。部分时间片会使
> 墙上延迟小于服务上界，二者仿真中都逐条校验。

## 4. 仿真验证

`simulate.py` 在 51 个配置上自动断言：

- 每个派发样本的轮内服务等待 ≤ `(n_r−1)q`（**全部通过**）；
- 每轮总 CPU 消耗 ≤ `n_r·q`；
- 轮中唤醒样本满足 `n_r·q + (n_{r+1}−1)q ≤ (2n_max−1)q`；
- 51 个用例中有 **38 个**观测最大值恰好等于紧界 `(n_max−1)q`。

饥饿场景关键数据（1 个不让步高优先级长任务 + `n−1` 个低优先级协程，
`q` 为时间片，`B` 为长任务突发）：

```
case                q  nmax  svcWaitMax   (n-1)q
starvation n=6      5    6        25        25     (B=5..5000 四列恒定 25)
starvation n=21     5   21       100       100     (B=5..5000 四列恒定 100)
starvation n=51    20   51      1000      1000     (B=20..20000 四列恒定 1000)
```

即把 `B` 放大 1000 倍，低优先级任务的最大轮内等待**纹丝不动**；
朴素调度器上该值随 `B` 线性增长（见下节）。

轮中唤醒（任务在一轮进行中被唤醒、下一轮才运行）：

```
case             q  nmax  wallMax   (2n-1)q
wakeups n=4      5    7      20         65
wakeups n=9      5   17      55        165
wakeups n=16    10   31     220        610
```

完整表格由仿真写入 `sched_demo/simulation_results.txt`。

## 5. 饥饿复现（修复前 vs 修复后）

`reproduce.py` 用**完全相同的任务体**跑两个调度器。

场景 A（一个不让步长任务 + 50 个低优先级协程，`q=20`）：

```
 burst B | 朴素：低任务首个 tick | 修复：低任务最大等待 | (n-1)q
    1000 |                 1000 |                 1000 | 1000
    5000 |                 5000 |                 1000 | 1000
   20000 |                20000 |                 1000 | 1000
```

朴素：首个低优先级 tick 时刻 == `B`（随负载无界增长）；
修复：恒为 `1000 == (n−1)q`，与 `B` 无关。

场景 B（优先级反转：低优先级持锁 + 5 个突发 1000 的中优先级任务 + 高优先级等待者）：

```
朴素 : H 被阻塞 5009 tick（随中等任务总工作量增长）
修复 : H 被阻塞    1 tick（界 ≈ 68，与中等突发无关）
```

## 6. 文件与运行方式

仅依赖 Python 3 标准库，无需安装任何第三方包。

```bash
cd /home/administrator/gsb/uid75/B

# 饥饿/反转复现（含断言：朴素必饥饿、修复必有界）
python3 -m sched_demo.reproduce

# 上界仿真（51 个配置；同时生成 simulation_results.txt）
python3 -m sched_demo.simulate

# 回归测试（17 个用例）
python3 -m unittest sched_demo.test_scheduler -v
```

文件：

- `sched_demo/scheduler.py` — 修复后的调度器（轮转 + 抢占 + 优先级继承）。
- `sched_demo/naive.py` — 有缺陷的朴素严格优先级调度器（复现用对照物）。
- `sched_demo/reproduce.py` — 稳定复现饥饿与优先级反转，前后对比。
- `sched_demo/simulate.py` — `(n, q, B)` 网格仿真，逐条断言等待上界。
- `sched_demo/simulation_results.txt` — 仿真数据表（由脚本重新生成）。
- `sched_demo/test_scheduler.py` — 回归测试。

### 回归测试覆盖的情形

- 单协程（含跨轮抢占后的 10/10/5 分段）；
- 全部同优先级（严格 FIFO）；
- 不同优先级的轮内排序、`Yield` 让出后下轮再入队；
- 优先级反转：朴素随中负载无界 vs 修复有界；继承开/关的轮内次序差异；
- 锁等待者 FIFO 唤醒顺序；
- **就绪队列为空**：无任务时 `run()` 立即返回、时钟为 0；
- 永久阻塞 / 双锁循环死锁检测（`DeadlockError`）、释放未持有锁报错；
- 确定性：相同（就绪顺序，优先级）两次运行 trace 逐事件相等；
- 饥饿回归：50 个低任务全部在第 1 轮被服务，且最大等待取紧界 `(n−1)q`。
